01 · Introducción

¿Qué es Atelier?

Una plataforma web que genera aplicaciones web completas a partir de una descripción en lenguaje natural. El usuario describe lo que quiere en un chat; 21 agentes de IA coordinados en 7 oleadas producen un proyecto Next.js funcional con base de datos, autenticación, API, componentes y tests — listo para arrancar.

Ejemplo validado: a partir de "app de yoga con admin, profesores y alumnos, reservas y pagos", Atelier genera en ~15 minutos un proyecto completo con 14 entidades, 18 pantallas, RBAC, pagos y suite de tests E2E.

02 · Arquitectura

Cómo está organizado el código

Hay dos mundos separados: la UI de la plataforma (app/) y el sistema de generación (lib/agents/).

lib/agents/ ├── prompts-v3/ ← system prompt de cada agente (.md) │ ├── bootstrap-devops.md │ ├── ux-ui-designer.md │ └── ... (un fichero por agente) │ ├── contracts-v3/ ← schema Zod que valida el output de cada agente (.schema.ts) │ ├── bootstrap.schema.ts │ ├── layout-tree.schema.ts │ └── ... (un fichero por agente) │ ├── runtime/ ← motor que invoca Claude y valida los outputs │ ├── runner-generator-v3.ts │ └── qa-gates/ │ ├── orchestrator-v3.ts ← coordina las waves y dependencias └── violations-router-v3.ts ← enruta errores al agente responsable
03 · El sistema agentico

Cómo está construido cada agente

Cada agente es la combinación de tres piezas que el runner une en tiempo de ejecución:

1. System prompt (.md)
Fichero Markdown en prompts-v3/. Define el rol del agente, qué inputs lee, qué output debe producir y las reglas que debe respetar. Se puede modificar sin tocar el código TypeScript.
2. Schema Zod (.schema.ts)
Define exactamente el JSON que debe producir el agente. Incluye refinements con invariantes de negocio. Si el output no pasa el z.parse(), se emite una violación.

El runner (runner-generator-v3.ts) lanza claude.exe como subproceso con el system prompt, lee el stdout por streaming, parsea el JSON y lo valida con el schema Zod. Si el agente produce también ficheros físicos (un .env.example, un schema.prisma…), el runner los escribe en el workDir. 

// contracts-v3/bootstrap.schema.ts — ejemplo de invariante
export const bootstrapOutputSchema = z.object({
  envManifest: z.array(z.object({
    key:    z.string(),
    source: z.enum(['env', 'generated', 'default']),
  })),
  healthcheckUrl: z.string().url(),
}).refine(
  (d) => d.envManifest.every(e => e.source !== 'hardcoded'),
  "Ninguna variable puede estar hardcodeada en el código"
);
04 · Las 7 waves

Qué hace cada agente

Los agentes dentro de una misma wave sin dependencias entre sí se ejecutan en paralelo con Promise.allSettled. El resultado de cada wave alimenta a las siguientes.

Wave 1
Bootstrap + Arquitectura
bootstrap-devops Genera la infraestructura de arranque: .env, Docker Compose, scripts de setup y el validador de entorno. Es la autoridad única sobre variables de entorno.
architect Lee el PRD y decide la estructura completa: páginas, entidades, roles, rutas. Su output es el contrato maestro que leen todos los agentes posteriores.
Wave 2
Diseño + Dominio
PARALELO
ux-ui-designer Define el design system: tokens de color, tipografía y genera mockups de pantallas con Stitch SDK.
layout-architect Diseña la estructura visual de cada página: secciones, composición y layout.
brand-identity Paleta de color exacta, escala tipográfica y microcopy (textos de botones, placeholders, errores).
domain-modeler Define todas las entidades del dominio, sus campos y relaciones. Se convierte en el schema Prisma.
persistence Genera el schema.prisma concreto con índices, constraints y configuración de BD.
seeds-shape Define la estructura de los datos de ejemplo que se cargarán en la BD.
Wave 3
Seguridad
PARALELO
service-layer Genera la lógica de negocio: las reglas de la app ("un alumno no puede cancelar la clase de otro").
auth-security Configura autenticación con Better Auth: registro, login, sesiones y tokens.
rbac-authorization Define los permisos por rol: qué puede hacer cada rol en cada ruta.
Wave 4
Frontend completo
api-backend Genera todos los endpoints REST con validación Zod y llamadas a la service-layer.
frontend-architect Define la organización del código React: hooks, providers, estructura de carpetas.
ui-components Genera los componentes React de la app usando shadcn/ui con los tokens de brand-identity.
forms-validations Genera formularios con React Hook Form + Zod: campos, validaciones y mensajes de error.
visual-adapter Convierte los HTMLs de Stitch en páginas JSX reales: conecta datos, aplica microcopy y preserva el diseño visual.
Wave 5 + 6
Datos y QA
seeds-fixtures Genera datos de ejemplo realistas para la base de datos.
tests-writer Escribe tests unitarios (Vitest) y E2E (Playwright) para los flujos principales.
qa-reviewer Revisa todos los artefactos buscando inconsistencias y emite violaciones con severidad warn / error / critical.
Wave 7
Visual QA
visual-qa Arranca la app generada con Playwright, ejecuta flujos reales con clicks, captura screenshots y detecta errores en runtime. Si encuentra fallos los enruta al agente responsable.
05 · Calidad

El fix loop

Si el qa-reviewer detecta violaciones tras una wave, el orquestador manda los errores de vuelta al agente responsable usando violations-router-v3.ts. El agente regenera su output con el contexto del error. Máximo 3 rondas. Si las violaciones son critical se detiene la generación; si son warn se acumulan en el informe final sin bloquear.
