01 · Introducción

¿Qué es Atelier?

Atelier es una plataforma SaaS que convierte una descripción en lenguaje natural en una aplicación web funcional y production-ready. El usuario describe lo que necesita en un chat; un sistema de 21 agentes especializados, coordinados en 7 oleadas secuenciales, genera el código, la base de datos, la autenticación, los tests y la infraestructura del proyecto.

Ejemplo real: Un usuario escribe "Quiero una app de gestión de clases de yoga con panel de administrador, perfil de profesor y portal para alumnos, con pagos y reservas". Atelier analiza la descripción, extrae los requisitos, y genera un proyecto Next.js completo con Prisma, autenticación por roles, API REST, componentes React y una suite de tests Playwright — listo para desplegar.

Wave 7 · QA Visual
Runtime & Visual QA
El agente visual-qa arranca la aplicación generada con Playwright, ejecuta flujos de cliente y administrador con clics reales, captura screenshots y detecta errores en runtime. Si detecta violaciones, las rutas de vuelta al agente responsable mediante el fix loop.

Fix loop: tras cada oleada, el agente qa-reviewer valida los artefactos producidos. Si detecta violaciones, las enruta al agente causante para que las corrija, hasta 3 rondas. Sólo si las violaciones persisten como critical se detiene la generación. Las de tipo warn se acumulan y se presentan en el informe final sin bloquear.

05 · Calidad del código

Contratos tipados entre agentes

Cada agente tiene su propio schema Zod. El orquestador valida el JSON de salida antes de pasarlo al siguiente agente. Esto elimina la posibilidad de que errores de formato se propaguen silenciosamente. 

// lib/agents/contracts-v3/bootstrap.schema.ts
export const bootstrapOutputSchema = z.object({
  envManifest: z.array(z.object({
    key:      z.string(),
    required: z.boolean(),
    source:   z.enum(['env', 'generated', 'default']),
  })),
  healthcheckUrl:    z.string().url(),
  crossPlatformOk:   z.boolean(),
  startupCommand:    z.string(),
}).refine(
  (d) => d.envManifest.every(e => e.source !== 'hardcoded'),
  "R0 — ninguna variable de entorno puede estar hardcodeada"
);
🔒 Invariantes en Zod
Los schemas incluyen refinements que comprueban reglas de negocio. Por ejemplo, R0 garantiza que ningún agente hardcodee variables de entorno en el código generado.
🧪 Tests de contratos
Cada schema tiene su propio fichero de tests. Los 233 tests en verde cubren schemas, validaciones de contratos, lógica del orquestador y comportamiento del runtime.
06 · Persistencia

Modelo de datos de Atelier

La base de datos de Atelier registra cada usuario, proyecto, generación y evento de agente. Esto permite reanudar generaciones interrumpidas e inspeccionar el historial completo.

Modelo Campos clave Descripción
User id (Clerk), email Usuario autenticado vía Clerk. El id es el proporcionado por Clerk.
Project id, slug, prd (JSON) Proyecto creado por el usuario. El campo prd almacena el documento de requisitos extraído en la fase Discover.
Generation status, startedAt, result Cada ejecución del orquestador. Status: pending | running | complete | failed.
AgentRun agent, status, output Registro de cada agente dentro de una generación. Almacena el artefacto JSON producido.
Event type, payload (JSON) Flujo de eventos del orquestador. Los 20 tipos de evento (wave.started, agent.completed, etc.) se persisten verbatim.
