## Compact Rules (inject into sub-agent prompts)

### TypeScript / Next.js (project-wide)

- TypeScript strict mode is non-negotiable: `"strict": true` plus `noUnusedLocals` and `noUnusedParameters` (per KICKOFF §Constraints).
- App Router (`app/(dashboard)/...`) — Server Components by default in `app/(dashboard)/` and `components/builder/`; opt into Client Components only when needed.
- Folder structure must match PRD §4 (`app/(dashboard)/...`, `lib/agents/`, `lib/db/`, `lib/sandbox/`, `lib/skeleton/`). Empty folders get a `.gitkeep`.
- Dependencies must be justified by the PRD — no "just in case" libraries.
- Package manager: `pnpm` if available, else `npm`. Never `yarn`.

### Generator output rules (apply to code Atelier *produces*, not Atelier itself)

- The 32 generation rules live in `ARCHITECTURE_BLUEPRINT.md`. Never inject all 32 into a single agent — each agent gets only its layer's subset (PRD §6 table).

### Commits / PRs

- `work-unit-commits`: structure commits as deliverable work units (feature + test + doc together), not file-type batches.
- `chained-pr`: if a PR would exceed ~400 changed lines, split into chained/stacked slices.
- `branch-pr`: follow the issue-first PR workflow.

### Documentation

- `cognitive-doc-design`: progressive disclosure, signposting, recognition over recall.
